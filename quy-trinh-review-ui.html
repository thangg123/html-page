Quy Trình Review UI Tính Năng

Đảm bảo UI được review sớm qua group feedback — Dev làm xong UI thì up lên, tiếp tục code bình thường, có feedback thì sửa.

Version 1.0 Cập nhật: 14/04/2026

📋 Tổng quan quy trình

Áp dụng cho toàn bộ team dev — Các tính năng có flow UI

BƯỚC 1

Nhận Task & Làm UI

  • Nhận task từ board (Jira/task management) — task có liên quan đến UI
  • Triển khai UI theo yêu cầu tính năng, bám sát design/spec
🎯 Dev tập trung làm xong phần UI trước, đảm bảo flow hoạt động đúng
BƯỚC 2

Up UI lên Group

  • Chụp hình hoặc quay video màn hình UI đã làm
  • Gửi lên group để mọi người xem và cho feedback
  • Tiếp tục code — Không cần chờ feedback, làm tiếp bình thường
📸 Làm xong UI → Chụp/quay → Gửi group → Làm tiếp
BƯỚC 3

Xử Lý Feedback

  • Có feedback → Xem xét, thống nhất với team → Sửa lại UI theo feedback
  • Không có feedback → Tiếp tục hoàn thành tính năng bình thường
🔄 Feedback được thống nhất → Sửa. Không có feedback → Tiếp tục code
💡 Mục đích: Phát hiện sai sót UI sớm, tránh phải sửa lại nhiều khi tính năng đã hoàn thành. Dev không bị block — up xong là làm tiếp.

🔄 Flow thực hiện

Từ lúc nhận task đến khi hoàn thành

START

Nhận task có UI

Dev nhận task từ board. Xác định task có flow UI cần review.

DEV

Triển khai UI

Code giao diện theo yêu cầu tính năng. Đảm bảo flow UI hoạt động đúng logic.

BẮT BUỘC
REVIEW

Chụp hình / Quay video UI

Chụp screenshot hoặc quay screen recording các màn hình UI đã làm xong. Đảm bảo thể hiện được flow người dùng.

SHARE

Gửi lên group

Up hình/video lên group để team xem. Không cần chờ phản hồi — tiếp tục làm việc bình thường.

CONTINUE

Tiếp tục code tính năng

Không bị block bởi bước review. Dev tiếp tục hoàn thiện logic, API, integration...

✅ Không có feedback

Tiếp tục hoàn thành task bình thường

💬 Có feedback

Xem xét feedback → Thống nhất → Sửa UI

DONE

Hoàn thành tính năng

UI đã được review (nếu có feedback thì đã sửa). Tính năng sẵn sàng cho QA.

ℹ️ Feedback chỉ cần sửa khi đã được thống nhất giữa các bên. Không phải mọi feedback đều phải thực hiện.

📌 Nguyên tắc

Những điều bắt buộc tuân thủ

✓  Bắt buộc chụp hình hoặc quay video — Không gửi text mô tả thay cho hình ảnh/video thực tế
✓  Up ngay khi UI xong — Gửi lên group ngay khi UI đã hoạt động được, không đợi đến lúc hoàn thành toàn bộ tính năng
✓  Không block công việc — Dev gửi xong thì tiếp tục code bình thường, không cần chờ ai review
✓  Feedback phải được thống nhất — Chỉ sửa UI khi feedback đã được thống nhất, không sửa theo ý kiến cá nhân chưa đồng thuận
✓  Áp dụng cho mọi task có UI — Bất kỳ tính năng nào có flow giao diện người dùng đều phải thực hiện quy trình này
⚠️ Nếu skip bước up UI → Rủi ro phát hiện sai sót muộn, phải rework nhiều khi đã code xong logic.
